# backend-account

Reusable Android/Kotlin backend/core module for OAuth 2.0 and OpenID Connect SSO.

> This library does not embed a provider-specific client secret or endpoint. Configure the authorization, token, and user-info endpoints supplied by your SSO provider (for example, the snippets at `https://account.aidislam.com/sso-snippets`).

## Install from JitPack

Add JitPack to `settings.gradle.kts` or `settings.gradle`:

```kotlin
pluginManagement {
    repositories {
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}

dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
        maven { url = uri("https://jitpack.io") }
    }
}
```

Then add the dependency:

```kotlin
dependencies {
    implementation("com.github.aidislam:backend-account:1.0.0")
}
```

The Maven coordinate is `com.github.aidislam:backend-account:1.0.0` when consumed from JitPack. If this project is published to a Maven repository under the `com.aidislam` group, the equivalent dependency is:

```kotlin
implementation("com.aidislam:backend-account:1.0.0")
```

## Configure

```kotlin
val account = BackendAccount(
    context = applicationContext,
    configuration = BackendAccountConfiguration(
        clientId = "your-public-client-id",
        authorizationEndpoint = "https://account.aidislam.com/oauth/authorize",
        tokenEndpoint = "https://account.aidislam.com/oauth/token",
        userInfoEndpoint = "https://account.aidislam.com/oauth/userinfo",
        redirectUri = "com.example.app://account/callback",
        scopes = setOf("openid", "profile", "email")
    )
)

// Open this URL in the system browser or a Custom Tab.
val loginUrl = account.createAuthorizationRequest().url
startActivity(Intent(Intent.ACTION_VIEW, loginUrl))
```

Handle the redirect in an Activity and exchange the returned authorization code:

```kotlin
val callback = account.parseCallback(intent.data ?: return)
val session = account.exchangeCode(callback.code, callback.state)
```

The `exchangeCode`, `refresh`, and `userInfo` calls are blocking network calls and must run on `Dispatchers.IO` (or another background executor). Never put a client secret in an Android application; use Authorization Code + PKCE with a public client.

## Security notes

- Use HTTPS endpoints and an app-specific redirect URI.
- Validate the returned `state` through `parseCallback` and retain the state generated by `createAuthorizationRequest`.
- Keep access tokens out of logs and URLs.
- Prefer an OS/browser-based flow over an embedded WebView for SSO.
- The included `SharedPreferencesTokenStore` is a small persistence adapter, not encryption. Replace it with Android Keystore-backed storage for production secrets.

## Local module usage

```kotlin
implementation(project(":backend-account"))
```

The module requires Android API 23+ and Kotlin 1.9+.
